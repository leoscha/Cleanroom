# Cleanroom v0.3.0 — Native PDF

v0.3.0 graduates digitally generated, text-based PDFs into a supported Cleanroom
format. Detection still uses the shared deterministic and private Ollama pipeline;
the release hardens extraction, source mapping, applied redaction, structural cleanup,
and verification rather than introducing OCR.

## Highlights

- Multipage and repeated-value PDF compatibility fixtures are part of the release
  evaluation gate.
- Mapping and redaction are tested across PyMuPDF-generated layouts, rotated text, and
  ReportLab-generated documents.
- Generated PDF evaluation now covers three layouts with perfect mapping, redaction,
  structural verification, and metadata sanitization requirements.
- Windows workspace locking is corrected and covered by cross-platform CI.

## Secure image handling

PDFs containing images now fail closed by default with
`PDF_IMAGES_WITHOUT_OCR`. Cleanroom cannot determine whether image pixels contain
sensitive information, even if the surrounding page has extractable text.

Operators may set `CLEANROOM_PDF_REJECT_IMAGES=false` only after independently
reviewing the images and accepting responsibility for their contents. This override
does not perform OCR or sanitize pixels. Image-only and likely scanned PDFs remain
rejected.

## Upgrade

```bash
python -m pip install --upgrade cleanroom-local==0.3.0
cleanroom version
cleanroom doctor
cleanroom evaluate --detector regex
```

Expected output begins with:

```text
Cleanroom v0.3.0
```

No database migration is required. See the [upgrade guide](../upgrade-guide.md) for
the PDF image-policy migration.

## Remaining boundaries

- No OCR or image sanitization.
- Encrypted, malformed, active-content, ambiguous, and likely scanned PDFs fail
  closed.
- Replacement labels do not reflow document layout.
- Verification covers documented extraction and structure paths; it does not prove
  forensic irrecoverability against every parser or recovery technique.
